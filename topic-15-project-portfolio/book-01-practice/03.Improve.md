# Make an evidence-led iteration

Implement the chosen improvement, preserving a copy or version of the earlier work. Run the acceptance test and relevant earlier checks. Record expected and actual results, including any new failure. Explain the cause of the defect and why the change fixes it. If the improvement introduces a trade-off, such as slower response after smoothing readings, state it explicitly.

Prepare a short demonstration that shows the main user task and one boundary or failure case. Keep the demonstration factual: show features that work, identify those that do not, and avoid substituting slides for actual operation. Use descriptive captions or narration and readable text. For a practice HTML portfolio, check all local links and media from a copied folder so accidental machine-specific paths are exposed.
