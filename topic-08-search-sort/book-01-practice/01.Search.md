# Trace and implement searching

Trace linear search on `[6, 3, 8, 2]` for targets 8 and 5. Record each inspected index and value. Predict the return value and number of item probes. The absent target requires checking all four items.

Trace binary search on `[3, 7, 11, 18, 23, 31, 42]` for targets 23 and 24. Use columns `low`, `high`, `middle`, middle value, and next update. Ensure the last unsuccessful step leaves an empty interval.

Implement both functions. Test empty input, one item found, one item absent, first item, final item, and a value between two existing items. For binary search, add a sorted list containing duplicates and accept any valid matching index. Do not require the first duplicate unless you deliberately implement that stronger contract.

Demonstrate why unsorted input violates binary search's precondition using `[8, 1, 6]` and target 8. Do not “fix” the search by sorting inside it: that changes its index meaning and adds preparation work. Explain the precondition to the caller instead.
