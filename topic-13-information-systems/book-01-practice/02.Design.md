# Follow a search

Check matching and no-match searches.

1. Clear the search box and submit. Check that all four records return.
2. Search for `river`, then `RIVER`. Both should return the same two titles in this ASCII example.
3. Search for `volcano`. Expect: “No matching books. Try a different title.”
4. Draw two small tables: Category and Book. Use the two River records in Learn. Label the primary keys and the `category_id` link.
5. Open `server.py` without stopping the running version. Find the `INSERT INTO book` block and the two River titles. Then find `SELECT` and `JOIN`.
6. Complete this trace in your notes:

```text
My input: river
Request: /api/books?q=river
Tables used: Book and Category
Returned titles: [write both]
Displayed availability: [write both]
```

**Check:** the database returns availability as 1/0; the page turns it into readable words.

Now sketch a search field, button, status line, and result list. Add one no-match and one error state. This is a wireframe: plain labelled boxes are enough. Choose one measurable requirement, such as “an unavailable book is labelled On loan in text”.
