# Run the indicator

Check the complete input-to-output path.

1. Open `solution.py` from the extracted pack and run it. After `Checks passed.`, it prints:

```text
raw,relative_level,enabled,warning
575,45.0,True,False
655,29.0,True,True
640,32.0,True,True
605,39.0,True,True
595,41.0,True,False
700,20.0,False,False
```

Here `True` means enabled/on and `False` means disabled/off. Compare each row with your paper trace. The final row stays off even though its level is low, because monitoring is disabled.

2. Save a copy as `my_controller.py`. Add `(700, True)` to the end of the input sequence. Run it. The new last row should be `700,20.0,True,True`: re-enabling at a low level turns the warning on.
3. In that copy, inspect `warning_state`. Identify the branch that gives disabled monitoring priority.
4. Add two temporary prints: `warning_state(35, False)` and `warning_state(35, True)`. Expect `False` and `True`.
