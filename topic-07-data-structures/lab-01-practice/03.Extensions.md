# Track runs and frequencies

Implement the longest strictly increasing consecutive run. For `[3, 5, 2, 4, 7, 7, 9]`, expect `[2, 4, 7]`. Trace `current` and `best` after every item. Test an empty list, a decreasing list, duplicate neighbours, and two equal-length best runs. Return the earliest run on a tie.

Count frequencies in `[1, 3, 3, 6, 1, 3]`. Expect face counts 2, 0, 3, 0, 0, 1. Check that their sum is 6. Do this on fixed data before generating any random trials.

Optional password exercise: implement five independent one-point rules: length at least 10, uppercase, lowercase, digit, and one of `!?@#`. Use only invented strings. Explain why the score is a practice measure and does not prove that a password is safe.

Finish by identifying which functions mutate their inputs and which return new values. The models here preserve input collections. Use the feedback note after your attempt. Classroom rubric: core aggregation (3), median cases and preservation (3), text/file validation (2), clear test evidence (2); extensions supply additional challenge rather than replacing the core.

## Weighted-check extension

Test `427` → 5 and explain why the old check digit fails to expose that particular transposition. These are explicit tests of the scheme's limitations, not implementation errors.
