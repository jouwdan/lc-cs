# Test record

| Test | Input | Expected output and why | Actual output | Pass or change needed |
|---|---|---|---|---|
| Normal | Choose a typical valid input | Predict before running | Record exactly | Explain |
| Boundary | Minimum, maximum or empty case | Derive from requirement | Record exactly | Explain |
| Invalid | Wrong type or out-of-range value | Define the rejection behaviour | Record exactly | Explain |

Keep failed tests as evidence of a useful discovery. After a fix, re-run both the failing test and a previously passing one. A test proves behaviour for its chosen input, not every possible case.
