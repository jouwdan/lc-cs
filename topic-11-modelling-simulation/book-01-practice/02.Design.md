# Predict the queue

Change events and trace the queue.

1. Copy the five-minute table from the Learn note. Cover its final column and fill it yourself.
2. In `my_queue.py`, change the lists to `arrivals = [1, 1, 1]` and `services = [0, 1, 0]`.
3. Predict the remaining queue before running. Expected: `[1, 1, 2]`, arrivals 3, served 1.
4. Change both lists to `[0, 0, 0]`. Expected: `[0, 0, 0]`.
5. Keep arrivals zero and set services to `[1, 1, 1]`. The queue still stays zero and served stays zero. Explain why.
6. Try arrivals `[1, 1, 1]` with services `[0, 0, 0]`. Expected: `[1, 2, 3]`.

For each run check `last queue = total arrivals - served`. For empty lists there is no last item; treat the final queue as zero.

**Small code task:** add a line that prints `max(history, default=0)`. For `[1,1,2]`, expect `2`. Why is that different from a person's longest waiting time?

**Check:** it counts people, not minutes. Measuring waiting time needs each person's arrival and service times.
