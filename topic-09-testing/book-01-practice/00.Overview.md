# Software design, testing, and debugging: practical

Use requirements and failing examples to guide a small, justified repair.

Allow 60–75 minutes. Use Python 3. The fictional rule is: 1–4 tickets cost 1200 cents each, 5–8 tickets cost 1000 cents each, and all other quantities are rejected. The discount applies to every ticket in the booking. The function returns integer cents and does not save a booking.

Write the test plan before repairing code. Submit the requirement, expected/actual table, a corrected function, and a short account of the fault. The checked solution and deliberately faulty teaching function are in `code/topic-09-testing/solutions.py`.

Keep a copy of the original so you can demonstrate that the selected test failed before the repair. Do not change the test expectation simply to make the status green.
