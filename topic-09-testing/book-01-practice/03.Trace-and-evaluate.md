# Explain the evidence

Record what changed and why it works.

## Core: finish the repair record

1. Compare the original quantity-5 failure with the corrected result: 6000 became 5000 cents.
2. Write three sentences: a requirement met with a named test; one untested limitation; the next useful check.
3. Confirm the evidence matches the program you saved. Preserve the original failing example and corrected tests.

Example structure: “All eight allowed quantities matched my hand calculations. I have not tested saving a booking because this calculator has no storage. Next I would test the complete saved-record workflow if storage were added.”

## Optional: JavaScript trace (10–15 minutes)

1. On paper, make columns statement / x / before / after. Trace:

```javascript
let x = 4;
let before = x++;
let after = ++x;
console.log(x, before, after);
```

2. Expect final values 6, 4, 6. Explain which assignment uses the old value and which uses the new value.
3. If Node.js is already available, save as `operators.js` and run `node operators.js`; otherwise use the answer trace. You do not need to install another runtime to complete this lesson.
4. Predict JavaScript `3 === "3"`, `3 == "3"`, and `"3" + 4`. Compare with Python `3 == "3"` and `"3" + 4`.
5. Check: JavaScript gives false, true and string `"34"`. Python gives False and then a TypeError for the mixed-type addition. Explain the role of automatic type conversion.
