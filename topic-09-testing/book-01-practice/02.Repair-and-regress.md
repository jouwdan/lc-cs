# Repair and retest

Fix the cause and rerun earlier checks.

## A. Correct the calculation

1. Create `booking_lab.py`. Copy the faulty function, rename it `booking_total_cents`, and change the comparison so quantity 5 is included in the discount.
2. Insert this validation at the beginning of its body:

```python
if type(quantity) is not int or not 1 <= quantity <= 8:
    raise ValueError("Enter a whole number from 1 to 8")
```

It rejects invalid types and ranges before calculating. It does not silently round a fractional value.

3. Below the function, add the following tests. The dictionary stores hand-calculated expected totals:

```python
if __name__ == "__main__":
    expected = {1: 1200, 2: 2400, 3: 3600, 4: 4800,
                5: 5000, 6: 6000, 7: 7000, 8: 8000}
    for quantity, total in expected.items():
        assert booking_total_cents(quantity) == total
    for invalid in [0, 9, -1, 2.5, "five", "5"]:
        try:
            booking_total_cents(invalid)
        except ValueError:
            pass
        else:
            raise AssertionError(f"Accepted invalid quantity: {invalid}")
    print("Booking checks passed")
```

`expected.items()` supplies quantity/total pairs. In the invalid-input checks, `pass` means the expected error happened; the `else` reports a failure if no error occurred. The final block runs only when this file is run directly.

4. Run `booking_lab.py`. Expect `Booking checks passed` with no traceback. Update all eight valid rows in your table.
5. State why rerunning quantity 1 after fixing quantity 5 is regression testing.
