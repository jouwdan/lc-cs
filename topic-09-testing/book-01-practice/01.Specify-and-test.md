# Reproduce a fault

Predict the result and expose the error.

## A. Write expected results first

1. In `booking-tests`, complete: “For quantity 5, the function must return ___ cents.” Add one criterion for quantity 0.
2. Create a test table with input / expected / actual / result. Calculate expectations for 1, 2, 4, 5 and 8; add 0, 9, 2.5 and `"five"` as rejected cases.
3. Label ordinary valid, boundary and invalid cases. Keep numeric text `"5"` separate: it is invalid for the calculation function but can be converted by the input interface.

## B. Run a complete faulty program

1. Save this as `faulty_booking.py`:

```python
def faulty_booking_total(quantity):
    if quantity > 5:
        price = 1000
    else:
        price = 1200
    return quantity * price

print("Actual cents:", faulty_booking_total(5))
assert faulty_booking_total(5) == 5000
```

2. Predict the actual value. Run it with the editor or `python3 faulty_booking.py`.
3. Expect `Actual cents: 6000`, followed by **AssertionError**. This deliberate failure is the evidence you are collecting; leave the original file unchanged.
4. Add actual 6000 and “fail” to the quantity-5 row. Explain why this is a logical error: the function runs, but follows the wrong price branch.
5. Write the hypothesis: “The test ___ excludes the boundary ___, so the wrong price ___ is chosen.”

**Check:** quantity 5 is the smallest valid input exposing this comparison defect. Missing validation is another issue, handled in the next step.
