# Design before running

List the input, output, two assumptions, and three decomposed tasks. Identify one detail you intentionally abstract away and explain why it does not affect capacity. Do not omit the available seat count.

Calculate the expected number of buses for 0, 1, 11, 12, 13, 24, and 25 passengers. Write the answers before coding. Use these values to challenge the tempting formula `passengers // 12 + 1`: explain precisely which cases it gets wrong.

Create pseudocode with an invalid-input branch and a remainder decision. Exchange it with a partner. They should be able to carry out the instructions without asking what “enough buses” means. Record one ambiguity they found and how you removed it.

Draw the processing and decision symbols correctly if you choose a flowchart. Label both decision exits. Trace your design for 25 passengers, recording the whole-number quotient, remainder, and final result.

Checkpoint: the expected result for 24 is 2, and for 25 it is 3. If your algorithm gives 3 for 24, fix the design before translating it into Python.
