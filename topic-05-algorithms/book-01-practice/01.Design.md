# Design the steps

Turn a bus problem into a clear plan.

Allow about 25 minutes. Write in `bus-plan`.

1. Copy these headings: **Input / Output / Assumptions / Invalid input**. Complete one sentence under each using the rules on Overview.
2. Write “Read → check → calculate → report”. Under each word, say what it does in this problem. This is decomposition.
3. Complete: “I keep ___ because ___; I omit ___ because ___.” Use available seats and bus colour to explain abstraction.
4. Calculate the blanks without code:

| Passengers | Full groups of 12 | Left over | Buses needed |
|---:|---:|---:|---:|
| 0 | 0 | 0 | 0 |
| 1 | | | |
| 11 | | | |
| 12 | | | |
| 13 | | | |
| 24 | 2 | 0 | 2 |
| 25 | | | |

5. Finish this pseudocode. `DIV` gives whole groups; `MOD` gives the remainder.

```text
INPUT passengers
IF passengers is not a non-negative whole number THEN
    OUTPUT "Invalid passenger count"
ELSE
    buses ← passengers DIV 12
    IF __________________ THEN
        buses ← __________
    ENDIF
    OUTPUT buses
ENDIF
```

6. Trace your steps for 25. Record the quotient, remainder and final output.
7. Read the steps literally, as if you were a computer. If you work with a partner, ask them to follow your version. Remove one unclear instruction.

**Check before continuing:** 12 needs 1 bus; 25 needs 3. If 12 gives 2, check whether you always add a bus.
