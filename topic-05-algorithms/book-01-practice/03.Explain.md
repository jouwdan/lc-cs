# Explain and extend

Explain the plan, then try an extension.

## Finish the core work

1. Write four sentences: what your bus algorithm calculates; when it adds one bus; why zero works; which test catches an exact-multiple mistake.
2. Circle each decision boundary in your work. For capacity 12, check 11, 12 and 13. For threshold 50, check 49, 50 and 51.
3. Check that your saved work contains the specification, algorithm and expected/actual table. Correct one mistake using the answers, then redo its test without looking.

## Optional extension A: generalise (10 minutes)

1. Replace 12 in the algorithm with `capacity`, a positive whole number.
2. Calculate the result for 31 and 32 passengers when capacity is 16. Both should need 2 buses.
3. Compare with repeatedly subtracting capacity until no passengers remain. Explain why a larger passenger count increases the number of subtraction steps.
4. Suggest a nearest-next-stop rule for a route. State that it is a heuristic: it may be useful quickly but does not guarantee the shortest whole route.

## Optional extension B: choose one puzzle (15–20 minutes)

Use the puzzle rules in **1. Learn**.

- **Robot:** draw the start and every possible first move. Cross out unsafe outcomes. Trace all seven trips and explain why trip 4 brings B back.
- **Counter game:** draw both moves from 3 counters. Label the opponent's turn. Explain why moving from 4 to 3 helps you.
- **Two piles:** draw every move from `(1,3)` and choose the one that leaves the opponent losing. Explain both possible replies.
- **Weighing:** draw all three first outcomes and their three second outcomes. Trace B, F and H; do not draw only one successful branch.

The optional [state-space checker](https://raw.githubusercontent.com/jouwdan/lc-cs/main/code/topic-05-algorithms/state_space.py) can be saved as `state_space.py` and run with `python3 state_space.py`. Expect `State-space and pile-game checks passed: shortest crossing solution is 7 trips`. Understanding its implementation is not required at this stage.
